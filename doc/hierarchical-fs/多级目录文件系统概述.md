# 多级目录文件系统概述

## 1. 完成的功能

- 在根目录下建立了 `/bin`、`/home`、`/tmp` 等层级目录，摆脱了原先平铺的根目录。
- 路径解析同时支持以 `/` 开头的绝对路径和相对进程当前工作目录的相对路径，支持 `.` 与 `..` 组件，并对路径做规范化，去除冗余分隔符、忽略 `.` 并对 `..` 弹栈。
- 每个进程维护自己的当前工作目录 `working_directory` 及其路径 `working_directory_path`，随 fork 继承，并由 `chdir` 更新。
- 进程 PCB 维护 `path_variable` 环境变量，`exec` 对裸命令名按冒号分隔的 PATH 逐个目录搜索。
- 实现了 `open`、`close`、`mkdir`、`unlink`、`chdir`、`getcwd`、`getdents`、`rename`、`getpath`、`setpath`、`lseek` 等文件系统系统调用。
- 实现了Linux 风格命令，如带类型前缀 `d`/`f` 与条目计数 `total`的`ls`、`cd`、`pwd`、`touch`、`mkdir`、`rm`、`mv`。
- `mv` 支持跨目录移动、目录移动，并带目录环检测。
- easy-fs 的 VFS 层为 inode 增加 parent 指针以支持 `..` 父目录跳转。
- 在路径不存在、权限不足、重复创建等情况下输出友好的用户提示。

## 2. 文件组织概述

内核侧的核心实现集中在系统调用层与虚拟文件系统层。系统调用入口位于 `os/src/syscall/fs.rs`，统一完成用户指针翻译、CWD 感知的根 inode 解析，再调用路径解析逻辑；文件系统与路径解析的公共逻辑位于 `os/src/fs/inode.rs`，其中的 `OSInode` 封装了读写偏移与底层 inode，`open_file_at`、`make_directory_at`、`unlink_at`、`rename_at` 等函数以「给定根 inode + 路径」的方式工作，另有 `split_path`、`normalize_path` 负责路径切分与规范化。进程的工作目录与 PATH 作为字段保存在 `os/src/task/process.rs` 的进程控制块中，并随 fork 继承。最底层的目录项与 inode 操作由 `easy-fs/src/vfs.rs` 提供，包括创建、删除、重命名、链接、父目录等原语。用户态命令以独立二进制形式放在 `user/src/bin/` 下，`cd` 因需要改变 shell 自身进程状态而作为内建命令集成在 `user_shell.rs` 中，与真实 `chdir`、内核 PATH 搜索、CWD 提示符协同工作。

## 3. 系统功能概述

系统启动后挂载根文件系统，创建 init 进程并进入 shell。shell 显示以当前工作目录为前缀的提示符，解析并执行用户输入。文件系统相关命令全部通过系统调用进入内核：路径由进程的 CWD 或根目录解析，目录项在 easy-fs 的 VFS 层完成增删改查。执行外部程序时，内核先按 PATH 或完整路径定位 ELF 并加载，子进程通过 fork 继承父进程的工作目录与 PATH，从而在 shell 中呈现与 Linux 一致的多级目录、路径跳转、命令搜索与文件操作体验。

## 4. 遇到的各种 bug

- 创建目录项时发生自旋锁死锁，内核卡死。根因是 easy-fs 的 `create_as` 在持有文件系统自旋锁的状态下又调用 `inode_number` 获取同一把锁，而 `spin::Mutex` 不可重入。修复方式是把父 inode 号在加锁前先计算好，再持锁执行创建，死锁消除。
- 路径字符串解析读越界。RISC-V 的 no_std 环境下字符串不会自动追加 null 终止符，内核 `translated_str` 依赖 null 判断结尾，因而读到缓冲区之外的脏数据，路径出现乱码或找不到文件。修复方式是在用户库增加 `null_terminated_path` 辅助函数，把路径复制进零初始化的定长缓冲区后再传给内核。
- RustSBI 固件与 QEMU 7.0 不兼容，启动后无任何输出且 CPU 忙循环，`make run` 表现为卡死。排查确认是固件问题而非代码问题，改用 OpenSBI 启动，Makefile 里以 `-bios default -kernel` 方式加载后恢复正常。
- `mv` 相对路径目标解析到错误位置。`sys_rename` 曾从旧路径推导解析根，导致相对路径的新目标被解析到根目录而非当前工作目录，相对路径 `mv` 时文件落到 `/` 下。修复方式是始终以 CWD 作为根传入，`rename_at` 内部对旧路径和新路径分别按绝对或相对独立解析。
- `normalize_path` 处理 `..` 时产生冗余路径。朴素的字符串拼接使路径规范化后出现 `/home/../bin` 这类含 `..` 的结果。修复方式是遇到 `..` 就弹栈，同时折叠 `.` 和多余分隔符，保证规范化结果不含 `.` 与 `..`。
- `mkdir /` 会创建空名字的目录项。`split_path` 对以 `/` 结尾的路径切出空文件名，空目录项破坏文件系统结构。修复方式是在 easy-fs 的 VFS 层对创建、删除、重命名、链接等操作统一拒绝空名字。
- `touch` 可覆盖目录项。`open` 带 `CREATE` 标志时遇到已存在的 inode 未检查其类型就直接返回，`touch` 现有目录被当作打开成功，随后可能被清空。修复方式是在 `open_file_at` 中若找到的 inode 是目录则返回失败。
- `touch` 不检测重复文件。对已存在的普通文件 `touch` 会静默成功，用户无法察觉重复。修复方式是在用户态 `touch` 中先判断文件是否已存在，存在则输出提示。
- 命令空参数导致 panic。`ls`、`mkdir` 等命令收到空参数时未做防护，直接访问数组越界或断言失败。修复方式是为各命令补充空参数判断并输出友好提示。
- `cd` 处理 `..` 时提示符路径错误。`chdir` 对 `..` 直接做字符串截断而未规范化，导致 `cd ../bin` 后提示符显示 `/home/../bin`。修复方式是修复 `..` 的路径计算逻辑并复用 `normalize_path` 规范化结果。
- 非 ELF 文件被执行导致 panic。执行普通文本等非 ELF 文件时内核在解析 ELF 头时 panic，整个系统崩溃。修复方式是在加载前校验 ELF magic 字节，不符则返回错误而非 panic。

## 5. 心得

### 心得

内核的设计中，安全性占了很重要的地位。rust自己的编译时规划资源回收时机，规避了大部分内存泄漏。在开发fs的时候，构建底层比想象中要简单一些，但是来到了用户命令行设计的时候，却频频出问题。在命令行上，或者说用户使用上，执行细节有很多，比方说，linux支持这样的写法：cd ../.././chdir/，复杂弯绕，但是内核必须保证在任何情况下都可以安全运行。还有一些意想不到的细节bug，如mv自己到自己的子文件夹，导致递归定义。尽管rust带来无与伦比的编译安全性，但是很多系统的谬误却不是一些内存泄漏可以解决的。

### rust 的安全性如何在这里体现

Rust 的安全性首先体现在所有权与借用上。内核里共享的 inode 全部通过 `Arc` 引用计数管理，路径以 `&str` 借用传递，编译器在编译期就排除了悬垂指针、双重释放和越界访问，进程退出与 fork 复制文件描述符表时无需手动管理内存。文件查找用 `Option` 表达结果，`lookup_path` 返回 `Option<Arc<Inode>>`，路径不存在时只能显式处理失败而非解引用空指针，`touch` 覆盖目录项、空文件名这类边界情况因此表现为返回错误而非内核崩溃。`OpenFlags` 与 `DiskInodeType` 等状态用枚举与 `bitflags` 表达，非法组合在编译期就被拒绝。共享可变状态全部包裹在 `spin::Mutex` 与 `UPIntrFreeCell` 中，只能通过 `exclusive_access` 独占访问，`Send` 与 `Sync` 约束保证跨核访问经过锁而非裸指针，尽管不可重入锁的死锁仍需运行期注意，数据竞争这一整类问题在类型层面被排除。少数必须接触裸指针的 `unsafe` 代码集中在页表操作与系统调用参数翻译处，边界清晰便于审计，其余代码默认安全。当不变量被破坏时 Rust 以带信息的 panic 终止而非静默破坏内存，非 ELF 文件被执行时暴露为可定位的 panic，而不是难以追踪的内存错误。
